# Архитектура VisualIDE для PVM

## Общая схема

```mermaid
flowchart LR
  subgraph Renderer["Интерфейс (renderer)"]
    B[Блоки Blockly] -- изменения --> G[Генератор HLC<br/>languages/pvm.json]
    G --> M[Monaco: HLC, ассемблер, листинг]
    D[Панель отладки, консоль]
  end
  subgraph Main["Основной процесс (Node.js)"]
    BU[build.cjs<br/>pvmcc → pvmc]
    DS[debug.cjs<br/>DebugSession]
    RS[pvmsim]
  end
  G -- main.hlc --> BU
  BU -- bin, lst, dbgmap, hex, c --> DS
  BU --> RS
  DS -- pvmdbg --machine --> SIM[(ВМ в pvmdbg)]
  DS -- pvmdbg --host --port --> BOARD[(плата COM3)]
  DS -- состояние, переменные --> D
```

Приложение построено на **Electron** (Windows, macOS, Linux). Интерфейс изолирован от системы
(`contextIsolation`, `sandbox`), а к файлам и процессам обращается только через API `window.vide` из
[`preload.cjs`](../src/main/preload.cjs).

## Структура

```
src/
  core/                    ядро без Electron (интерфейс, CLI, тесты)
    languages.js           язык из languages/pvm.json + генерация кода
    generators/template.js шаблонный генератор; маркеры «строка HLC → блок»
    generators/common.js   неподдерживаемые блоки, отчёт генерации
    toolbox.js             палитра (только то, что есть в HLC)
    types.js, translit.js  вывод типов, транслитерация имён
    project.js             формат файла .vide (блоки + точки останова)
    blocks.js              блоки «комментарий», «код», «выражение»
  main/
    main.cjs               окно, меню, IPC
    preload.cjs            мост window.vide
    pvm/tools.cjs          поиск утилит PVM
    pvm/build.cjs          сборка и разбор ошибок pvmcc
    pvm/artifacts.cjs      карта отладки (.dbgmap) и листинг (.lst)
    pvm/debug.cjs          драйверы pvmdbg и сессия отладки
    pvm/serial.cjs         список последовательных портов
    runner.cjs             построчный фильтр вывода pvmsim
  renderer/                интерфейс: app.js, debug-view.js, settings-dialog.js, …
  cli/vide.mjs             hlc / build / run без интерфейса
languages/pvm.json         описание PVM HLC: шаблоны, помощники, блоки категории «PVM»
examples/                  примеры (они же эталоны тестов)
```

## Ключевые решения

**Протокол с устройством не переписывается.** Кадры, CRC, COM-порт и пересинхронизация потока
остаются в `pvmdbg`, которая проверена на железе. VisualIDE общается с ней текстом:

- `MachineDriver` использует машинный протокол `pvmdbg --machine` (`ok …` / `error …`, `run` + `poll`).
  Через него работают симулятор и плата с прошитой программой. Строки, которые не являются ответом
  протокола (например, `SVC print -> 5`), считаются выводом программы.
- `HostCliDriver` использует интерактивную сессию `pvmdbg --host`: ответ на команду — это всё, что
  напечатано до следующего приглашения `(pvmdbg) `. Машинного протокола для `--host` нет, а `run`
  блокирует и прерывается только Ctrl+C, поэтому при отладке выполнение идёт шагами, которые отдаёт
  `DebugSession`. Так пауза работает всегда. Для запуска без отладки используется быстрый `run`.

**Отладка по блокам.** Перед кодом каждого оператора генератор вставляет маркер с id блока
(`STATEMENT_PREFIX` Blockly). После генерации маркеры вырезаются, и получается таблица
«строка HLC → блок». Дальше работает цепочка
`PC → строка (main.dbgmap) → блок`: так подсвечивается текущий блок. Точки останова хранятся как id
блоков и переводятся в адреса по той же цепочке в обратную сторону. Они не зависят от того, как
сдвигается код при редактировании.

**Шаги по строкам — в `DebugSession`.** «С обходом» отслеживает выполненный `CALL`: указатель кадра
растёт только на `ENTER`, поэтому проверка по FP опоздала бы на инструкцию. Дальше шагаем до возврата
на адрес после `CALL` в тот же кадр. «С выходом» шагает до `RET` из текущего кадра. Код библиотек
(`lib/time.hlc`) проходится без остановок.

**Переменные по листингу.** Адреса глобальных переменных и портов берутся из раздела `# variables:`
листинга `pvmc -l` и читаются командой `data` (соседние адреса — одним запросом). Имена из HLC
сопоставляются с именами переменных в блоках через таблицу, которую возвращает генератор.

**Сборка в папку рядом с проектом.** Сборка лежит в `<проект>.build/`, и это обычные файлы PVM:
`main.hlc`, `.pvms`, `.bin`, `.hex`, `.c`, `.lst`, `.dbgmap`. Их можно прошить или передать
`pvminit` / `make`.

## Тесты

`npm test`:

- `core.test.mjs` — транслитерация, типы, шаблонный движок и таблица строк, перевод всех блоков палитры,
  разбор листинга, карты отладки, ошибок `pvmcc` и вывода `pvmdbg`.
- `pvm.test.mjs` — с настоящими утилитами: сборка каждого примера и выполнение в симуляторе со сверкой
  переменных, точки останова, шаги с обходом и с выходом. С `PVM_BOARD_PORT=COM3` пример выполняется
  ещё и на плате.
