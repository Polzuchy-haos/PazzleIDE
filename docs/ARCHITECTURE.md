# Архитектура PazzleIDE для PVM

## Общая схема

```mermaid
flowchart LR
  subgraph Renderer["Интерфейс (renderer)"]
    B[Блоки Blockly] -- изменения --> G[Генератор HLC<br/>languages/pvm.json]
    G --> M[Monaco: HLC, ассемблер, листинг]
    D[Панель отладки, консоль]
  end
  subgraph Main["Основной процесс (Node.js)"]
    BU[build.cjs<br/>pvmcc → pvmc]
    DS[debug.cjs<br/>DebugSession]
    RS[pvmsim]
  end
  G -- main.hlc --> BU
  BU -- bin, lst, dbgmap, hex, c --> DS
  BU --> RS
  DS -- pvmdbg --machine --> SIM[(ВМ в pvmdbg)]
  DS -- pvmdbg --host --port --> BOARD[(плата COM3)]
  DS -- pvmdbg --tcp --> BR[мост цели] --> BOARD2[(плата по сети)]
  DS -- состояние, переменные --> D
  T[targets.cjs<br/>цели, переменные, команды] --> BU & DS & FL[команда прошивки]
```

Приложение построено на **Electron** (Windows, macOS, Linux). Интерфейс изолирован от системы
(`contextIsolation`, `sandbox`), а к файлам и процессам обращается только через API `window.pazzle` из
[`preload.cjs`](../src/main/preload.cjs).

## Ключевые решения

**Протокол с устройством не переписывается.** Кадры, CRC, COM-порт и пересинхронизация потока
остаются в `pvmdbg`, которая проверена на железе. PazzleIDE общается с ней текстом:

- `MachineDriver` использует машинный протокол `pvmdbg --machine` (`ok …` / `error …`, `run` + `poll`).
  Через него работают симулятор и плата с прошитой программой. Стек вызовов и переменные по именам —
  глаголы `frames`, `vars N`, `globals` (карта отладки передаётся через `--map`).
- `HostCliDriver` использует интерактивную сессию `pvmdbg --host`: ответ на команду — это всё, что
  напечатано до следующего приглашения `(pvmdbg) `. Машинного протокола для `--host` нет, а `run`
  блокирует и прерывается только Ctrl+C, поэтому при отладке выполнение идёт шагами, которые отдаёт
  `DebugSession`. Так пауза работает всегда. Для запуска без отладки используется быстрый `run`.

**Отладка по блокам.** Перед кодом каждого оператора генератор вставляет маркер с id блока
(`STATEMENT_PREFIX` Blockly). После генерации маркеры вырезаются, и получается таблица
«строка HLC → блок». Дальше работает цепочка
`PC → строка (main.dbgmap) → блок`: так подсвечивается текущий блок. Точки останова хранятся как id
блоков и переводятся в адреса по той же цепочке в обратную сторону. Они не зависят от того, как
сдвигается код при редактировании.

**Шаги по строкам — в `DebugSession`.** «С обходом» отслеживает выполненный `CALL`: указатель кадра
растёт только на `ENTER`, поэтому проверка по FP опоздала бы на инструкцию. Дальше шагаем до возврата
на адрес после `CALL` в тот же кадр. «С выходом» шагает до `RET` из текущего кадра. Код библиотек
(`lib/time.hlc`) проходится без остановок.

**Стек вызовов и переменные — от pvmdbg.** `pvmcc` пишет в карту отладки функции, параметры, локальные и
глобальные переменные, `pvmdbg` по ней восстанавливает кадры с устройства. `DebugSession` после каждой
остановки берёт кадры с переменными (`frames` + `vars N` или `bt full`) и глобальные (`globals`) и
добавляет к каждому кадру строку HLC, а интерфейс по ней находит блок места вызова. Имена из HLC
сопоставляются с именами переменных и функций в блоках через таблицу, которую возвращает генератор.
Со старым `pvmdbg` глобальные читаются по листингу `pvmc -l` командой `data`.

**Сборка в папку рядом с проектом.** Сборка лежит в `<проект>.build/`, и это обычные файлы PVM:
`main.hlc`, `.pvms`, `.bin`, `.hex`, `.c`, `.lst`, `.dbgmap`. Их можно прошить или передать
`pvminit` / `make`.

**Документы и рабочие столы.** Открытый файл — документ: проект пазлов (своё рабочее поле Blockly,
сгенерированный HLC, точки останова на блоках) или текст (модель Monaco; точки останова — декорации
модели, поэтому переезжают со строкой при правке). У каждого документа свои модели «Ассемблер» и
«Листинг» и последняя сборка. Редактор Monaco один, ему подставляется модель активного документа;
рабочих полей Blockly столько, сколько открыто проектов (так у каждого своя история отмены).
Рабочий стол только решает, что видно: «Пазлы» и «HLC» показывают один документ своего вида, «IDE» —
дерево папки и вкладки. Открытые документы сохраняются в сеансе: сохранённые файлы при запуске
перечитываются с диска, несохранённые правки — из сеанса.

**Цели — данные, а не код.** Цель — запись в настройках: режим, подключение (порт или TCP), мост,
ограничения памяти, команды прошивки и запуска, переменные окружения. Основной процесс по текущей
цели строит аргументы `pvmdbg` (`--port`/`--tcp`), запускает мост и ждёт его готовности, подставляет
`${...}` в команды и передаёт те же значения как `PAZZLE_*`. Команды идут через оболочку и завершаются
деревом процессов (`taskkill /T` на Windows, группа процессов в остальных системах).

**Ограничения памяти — средствами компилятора.** Вместо своей проверки размеров PazzleIDE дописывает
`section code/ram/stack` в конец собираемого `main.hlc`; остальное делают `pvmcc` и `pvmc`. Строки кода
не сдвигаются, поэтому таблица «строка → блок» и карта отладки остаются верными.

**Библиотеки пазлов.** Элемент библиотеки — сериализованная стопка блоков без id, с переменными по
имени. Сохранение функции добавляет функции, которые она вызывает, и константы, которые она использует.
Блоки палитры библиотеки помечены (`block.data`); когда такой блок появляется в проекте, обработчик
событий рабочего поля (он подписан раньше блоков Blockly) добавляет недостающие определения в ту же
группу событий — до того, как Blockly успел бы создать пустое определение функции, и одним «Отменить».

## Тесты

`npm test`:

- `core.test.mjs` — транслитерация, типы, шаблонный движок и таблица строк, перевод всех блоков палитры,
  svc с любым числом аргументов и миграция старых проектов, библиотеки (сохранение с зависимостями,
  подключение в проект), ограничения памяти и переменные целей, разбор листинга, карты отладки,
  ошибок `pvmcc` и вывода `pvmdbg`.
- `pvm.test.mjs` — с настоящими утилитами: сборка каждого примера и выполнение в симуляторе со сверкой
  переменных, точки останова, шаги с обходом и с выходом, ограничения памяти, цель по TCP с мостом
  (`pvmboard`, если есть). С `PVM_BOARD_PORT=COM3` пример выполняется ещё и на плате.
