# Сборка, запуск и отладка

PazzleIDE переводит блоки в код PVM HLC, а дальше работает утилитами проекта PVM: `pvmcc` и `pvmc`
собирают программу, `pvmsim` и `pvmdbg` её выполняют и отлаживают. С устройством общается только
`pvmdbg`, которая уже проверена на железе. Протокол отладки в PazzleIDE не переписан.

## Где взять утилиты

В дистрибутив PazzleIDE утилиты PVM уже встроены (`resources/pvm`). Их собирает из исходников
`npm run pvm:bundle`: в комплект входят `pvmcc`, `pvmc`, `pvmsim`, `pvmdbg`, `pvmdisasm`, `pvminit`,
`pvmboard` (плата-процесс по TCP, если есть в сборке PVM), `lib/` и `libwinpthread-1.dll`, а `VERSION.txt` хранит коммит PVM. PazzleIDE ищет утилиты по порядку:

1. **Файл → Настройки → Утилиты PVM** — чтобы взять другую сборку PVM;
2. переменная окружения `PVM_HOME`;
3. встроенные в дистрибутив;
4. `../pvm/Release` рядом с папкой PazzleIDE (так репозитории лежат при разработке);
5. `vendor/pvm` (результат `npm run pvm:bundle`);
6. `PATH`.

Какая папка используется, видно справа в строке состояния. Щелчок по ней открывает настройки.

## Сборка (Ctrl+B)

| Шаг | Команда | Результат |
|---|---|---|
| код из блоков или открытый файл `.hlc` | — | `main.hlc` (+ ограничения памяти цели в конце) |
| компиляция | `pvmcc main.hlc -o main.pvms [-I папка исходника]` | ассемблер и оценка глубины стека |
| ассемблирование | `pvmc main.pvms -o main.bin -f bin -l main.lst -g main.dbgmap` | байткод, листинг с картой памяти, карта отладки |
| прошивочные форматы | `pvmc … -f hex`, `pvmc … -f carray` | `main.hex` для прошивальщика, `main.c` для вшивания в прошивку |

Результаты лежат в папке сборки: для сохранённого файла это `<имя>.build` рядом с ним (`.pzl` или `.hlc`),
для несохранённого — папка в данных приложения. У файла `.hlc` `import` ищется и рядом с ним (`-I ..`);
на Windows это работает только в папках с латинскими именами — `pvmcc` не открывает пути с кириллицей. Её открывает **Файл → Открыть папку сборки**.

- Ассемблер и листинг показаны во вкладках **Ассемблер** и **Листинг** рядом с кодом HLC.
- Справа в строке состояния выводится сводка: размер кода, занятая RAM и худшая глубина стека.
- При ошибке компиляции блок, из которого получилась ошибочная строка, получает значок предупреждения
  и выделяется, а строка HLC подчёркивается.

Запуск и отладка собирают программу сами, если блоки изменились после последней сборки.

## Цели

Цель — где выполняется программа и как к ней подключаться. Она выбирается в списке **Цель** на панели
инструментов, а настраивается кнопкой рядом с ним или в **Сборка → Цели…**. Встроенные цели можно
менять, к ним — добавлять свои: например, плату по TCP, плату за утилитой-мостом или цель с командой
прошивки. Цели хранятся в настройках пользователя и общие для всех проектов.

| Режим | Как выполняется | Чем запускается |
|---|---|---|
| **Симулятор** | ВМ на этом компьютере | запуск: `pvmsim`; отладка: `pvmdbg main.bin --machine` |
| **Плата: программа с хоста** | программа остаётся на компьютере, плата исполняет её по одной инструкции; прошивать ничего не нужно | `pvmdbg --host main.bin --port COM3 --baud 9600` |
| **Плата: прошитая программа** | программа уже в прошивке платы; карта отладки берётся из текущей сборки | `pvmdbg --port COM3 --baud 9600 --machine` |

У цели есть:

- **Подключение к плате** — последовательный порт и скорость (их можно менять и на панели инструментов,
  ⟳ обновляет список портов) или **TCP**: `хост:порт` либо только порт (эта машина). По TCP ходят те же
  кадры отладчика: `pvmdbg --tcp 192.168.1.20:5555`. Значения по умолчанию — **COM3** и **9600**.
- **Мост** — команда, которую PazzleIDE запускает перед подключением и завершает после (вместе с её
  дочерними процессами): мост UART↔TCP, `pvmboard`, ssh-туннель, своя утилита. Подключение начинается,
  когда в выводе моста появится заданный текст (регулярное выражение) или через заданное число
  миллисекунд. Вывод моста идёт в консоль с пометкой `[мост]`.
- **Ограничения памяти** — код (байт), RAM и стек (слов). См. ниже.
- **Команды** «Прошить / загрузить» и «Запустить» (своя вместо встроенной) и **переменные окружения**.

Пример цели «плата без железа»: режим «прошитая программа», TCP `5555`, мост
`"${pvmboard}" "${bin}" --listen ${tcpPort} --paused --once`, готовность — `debugger on`.

### Ограничения памяти

Размеры кода, RAM и стека платы, под которую пишется программа. Их понимает сам компилятор: при сборке
PazzleIDE добавляет в конец `main.hlc` объявления `section code/ram/stack` (номера строк не сдвигаются),
поэтому программа, которая не помещается, не собирается: переменная, не влезающая в RAM, отмечается
на блоке, а слишком большой код и глубокий стек — ошибкой в консоли. Заводские значения встроенных и новых
целей — код 1024 байт, RAM и стек по 64 слова (кнопка «Заводские значения» возвращает их). Пустое поле —
размер самой PVM по умолчанию (код 65535 байт, RAM 64 и стек 1024 слова). Если секцию объявляет сам код (блок «память» или
`section` в HLC), побеждает он, и консоль об этом пишет. Запуск в симуляторе получает те же стек и RAM
(`pvmsim --stack --ram`); отладчик в симуляторе работает с размерами по умолчанию.

### Команды и переменные

Команды выполняются оболочкой системы (`cmd.exe` или `sh`), так что работают кавычки, `&&` и
перенаправления. Вывод идёт в консоль, «Стоп» завершает команду вместе с дочерними процессами.
Рабочая папка — папка рабочего стола «IDE», иначе папка файла.

В командах подставляются переменные `${имя}` (пути с пробелами берите в кавычки: `"${hex}"`), системные
переменные — `${env:ИМЯ}`. Те же значения процесс получает в окружении как `PAZZLE_ИМЯ`
(`${projectDir}` → `PAZZLE_PROJECT_DIR`) — удобно для своих скриптов.

| Переменная | Значение |
|---|---|
| `projectFile`, `projectDir`, `projectName` | открытый файл (.pzl или .hlc), его папка, имя без расширения |
| `workspaceFolder` | папка рабочего стола «IDE» (иначе папка файла) |
| `buildDir`, `hlc`, `pvms`, `bin`, `hex`, `carray`, `lst`, `map` | папка сборки и её файлы |
| `toolsDir`, `pvmcc`, `pvmc`, `pvmsim`, `pvmdbg`, `pvminit`, `pvmboard` | утилиты PVM |
| `target`, `port`, `baud`, `tcp`, `tcpHost`, `tcpPort` | цель и её подключение |
| `codeSize`, `ramSize`, `stackSize` | ограничения памяти цели |
| `appDir` | папка PazzleIDE |

Поле «Переменные окружения» добавляет свои переменные (строки `ИМЯ=значение`, в значениях тоже
работают `${...}`). Вывод консольных программ Windows в кодировке OEM (cp866) распознаётся и
показывается по-русски.

## Прошивка (Ctrl+U)

Кнопка **Прошить** собирает программу и выполняет команду прошивки текущей цели. Сама PVM прошивальщика
не содержит, поэтому команда своя для каждой платы, например:

```text
STM32_Programmer_CLI -c port=SWD -w "${hex}" -v -rst
make -C "${workspaceFolder}/firmware" flash PROGRAM="${carray}"
avrdude -p m328p -c arduino -P ${port} -b 115200 -U flash:w:"${hex}":i
```

Если у цели нет команды, кнопка открывает настройки цели на поле прошивки. Успех — код возврата 0.

## Запуск без отладки (Ctrl+F5)

- **Своя команда.** Если у цели задана команда «Запустить», выполняется она (с теми же переменными).
- **Симулятор.** В консоль попадает только то, что программа вывела блоком «напечатать»: он пишет
  значение в регистр вывода `OUT @ 0x4007`, как примеры PVM, а каждая такая запись (`STORE 0x4007`)
  становится строкой вывода. Остальная трассировка `pvmsim` отфильтровывается. Полную трассировку
  включает флажок «Полный вывод симулятора» в настройках. `pvmsim` останавливается по своему лимиту
  шагов (`--steps`, по умолчанию 100 000 инструкций).
- **Плата (программа с хоста).** Программа выполняется до `HALT`, после чего в консоль выводятся
  значения переменных. «Стоп» прерывает выполнение, завершая процесс `pvmdbg`. В этом случае плата
  остаётся на паузе до следующей сессии отладчика.

## Отладка (F5)

| Действие | Клавиша | Что делает |
|---|---|---|
| Отладка / продолжить | F5 | собрать, подключиться, встать в начале программы; дальше — выполнять до точки останова |
| Пауза | F6 | остановить выполняющуюся программу |
| Шаг с обходом | F10 | следующий блок; вызовы функций выполняются целиком |
| Шаг с заходом | F11 | следующий блок, с заходом в функцию |
| Шаг с выходом | Shift+F11 | выполнить функцию до возврата |
| Одна инструкция | Ctrl+F11 | одна инструкция ВМ |
| Сначала | Ctrl+Shift+F5 | вернуть программу в начало |
| Остановить | Shift+F5 | закончить сессию (плата продолжит свою программу) |
| Точка останова | F9 | на выделенном блоке или на строке HLC под курсором |

- **Точки останова ставятся на блоки**: правый щелчок по блоку → «Точка останова», клавиша F9 или
  щелчок слева от строки кода HLC. У блока с точкой останова красная обводка. Точки сохраняются в проекте.
- **В файле HLC** (рабочие столы «HLC» и «IDE») точки останова ставятся на строки: щелчок слева от строки
  или F9. Они переезжают вместе со строкой при правке и переживают перезапуск IDE.
- **Текущий блок** обведён жёлтым, а строка HLC отмечена стрелкой.
- Во вкладке **Отладка** показано, где стоит программа (строка, функция, PC/SP/FP и текущая инструкция).
  Там же глобальные переменные с именами из блоков и портами `@0x4000…`; значения, изменившиеся на
  последнем шаге, выделены. Рядом верхние слова стека ВМ.
- Переменные читаются по адресам из листинга `pvmc -l`, поэтому видны и на плате.

### Особенности целей

| | Симулятор | Плата: с хоста | Плата: прошитая |
|---|---|---|---|
| Точки останова | 4 (слоты агента) | без ограничения (на хосте) | 4 (слоты агента) |
| Пауза во время выполнения | да | да | да |
| Скорость на 9600 бод | — | ~20 инструкций/с при отладке, ~35 при запуске без отладки | обычная скорость платы |
| Вывод блока «напечатать» | последнее значение — переменная `OUT` | то же | то же |
| Стек вызовов и переменные функций | да | да (`bt full`) | да |

**Программа с хоста при отладке выполняется шагами, которые отдаёт сама IDE.** Машинного протокола
(`--machine`) для `--host` в `pvmdbg` пока нет. Интерактивная команда `run` там блокирующая и
прерывается только Ctrl+C, а дочернему процессу из графического приложения на Windows его не послать.
Шаги через интерактивную сессию дают паузу всегда, но работают примерно вдвое медленнее `run`.
Если добавить `--host` в машинный режим `pvmdbg`, PazzleIDE сможет переключиться на него без изменений
интерфейса.

**RAM платы между сессиями не очищается** (как и при перепрошивке). Если программа рассчитывает на
нулевые переменные, присвойте им значения в начале.

### Стек вызовов и переменные

Начиная с PVM `074c17f`, `pvmcc` записывает в карту отладки границы функций, параметры, локальные
переменные (смещение от FP) и глобальные переменные, а `pvmdbg` восстанавливает по устройству цепочку
кадров. Во вкладке **Отладка**:

- **Стек вызовов** — функции с аргументами и строками, от текущей (`#0`) до `main`. Рекурсия видна
  целиком: `факториал(n=5) ← факториал(n=6) ← факториал(n=7) ← main()`. Щелчок по кадру выбирает его:
  блок, из которого была вызвана функция, обводится синим пунктиром, строка вызова подсвечивается в HLC.
- **Переменные функции** — параметры (`FP-3` и глубже) и локальные переменные (`FP+0…`) выбранного кадра.
  Локальная переменная, которая ещё не объявлена в этой точке, или кадр на `ENTER`/`RET`
  показываются как «ещё нет».
- **Глобальные переменные** — по адресам из карты, массивы целиком, порты и регистр вывода `OUT`.
- Имена показываются так, как они называются в блоках, а в скобках — имя в HLC.

В машинном режиме это команды `frames`, `vars N` и `globals`. В режиме «с хоста» используются
интерактивные `bt full` и `globals`. Со старым `pvmdbg` без этих команд стек вызовов не показывается,
а глобальные переменные читаются по листингу, как раньше.

## Экспорт проекта (Makefile, VS Code)

**Файл → Экспорт проекта** записывает в выбранную папку `main.hlc` из блоков и запускает `pvminit`.
Получается обычный проект PVM: `make`, `make run`, `make debug`, `make board`, а F5 работает в VS Code
с расширением `vscode-pvm`.
